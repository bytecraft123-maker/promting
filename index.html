Chapter 01

Introduction to Prompt Engineering

Big idea: A language model produces a continuation of the information it receives. Prompt engineering is the practice of making that continuation useful, relevant, and reliable.

The Central Question

Imagine giving a language model the words: "The most important discovery of the experiment was…" The words surrounding the request determine which kind of continuation is likely.

Evolution of Models

  • 1940s onward: Statistical language models and Markov approaches.
  • 2014: Sequence-to-sequence (seq2seq) models with encoders and decoders.
  • 2017: The Transformer architecture introducing attention mechanisms.
  • 2018–Present: GPT (Generative Pre-trained Transformer) models enabling powerful context-sensitive prompting.

Anatomy of a Well-Designed Prompt

A designed prompt does four things better than a vague one:

  1. States the target audience.
  2. Supplies scope and sequence.
  3. Specifies presentation format.
  4. Sets constraints on length and terminology.
Chapter 02

Understanding How Language Models Work

Big idea: To use a language model well, understand what it actually processes: tokens, probability distributions, and context.

Tokens & Context Windows

Models operate on token IDs rather than raw human words. Formatting, punctuation, and language choice directly impact token counts and context budget.

Autoregression & Temperature

Generation happens one token at a time based on probability scores (logits converted via softmax). Temperature controls the sharpness of this distribution:

  • Low Temperature (0.0–0.3): More stable and predictable phrasing.
  • Medium Temperature (0.5–0.8): Balanced variation in tone.
  • High Temperature (0.9+): Creative variation with higher risk of instability.

Hallucinations

A hallucination occurs when fluent text presents false, unsupported, or fabricated facts, citations, or URLs. Grounding and verification are essential safeguards.

Chapter 04

Designing Applications with Language Models

Big idea: The model produces text; the application turns a real-world problem into the right model input and turns the output into a useful result.

Think in Loops, Not Isolated Prompts

An LLM application is a complete transformation loop: user goal $\rightarrow$ context collection $\rightarrow$ prompt assembly $\rightarrow$ model call $\rightarrow$ validation and action.

Tools and External Actions

Applications can provide tools (read-only vs. write-capable) allowing models to retrieve live data, execute queries, or modify external states securely under application validation.

Chapter 05

Prompt Content & Retrieval-Augmented Generation (RAG)

Big idea: The quality of an LLM response depends not only on the instruction, but also on which information enters the prompt.

Static vs. Dynamic Content

Static content defines general tasks and constraints, while dynamic content brings in case-specific information at runtime.

Retrieval-Augmented Generation (RAG)

RAG connects search systems with generative LLMs:

  1. Indexing: Splitting documents into snippets and generating embeddings.
  2. Retrieval: Finding the most relevant snippets matching a user query (via lexical or neural search).
  3. Generation: Grounding the model's response strictly within the retrieved context.
