Module 01 Comprehensive Notes

Introduction to Prompt Engineering

A language model produces a continuation of the information it receives. Prompt engineering is the practice of making that continuation useful, relevant, and reliable.

The Core Transformation Challenge

When you prompt a language model with an open-ended statement like "The most important discovery of the experiment was…", the underlying neural network predicts the most probable token continuation based on its massive pre-training distribution.

Without structured constraints, instructions, and contextual guidance, the model may wander into irrelevant text genres (such as continuing a fiction story instead of a lab report). Prompt engineering bridges user intent and model output by shaping the immediate environment in which text generation unfolds.

Historical Model Evolution

  • Statistical / Markov: Early probability tables over fixed n-gram word windows.
  • Seq2Seq (2014): Encoder-decoder neural translation models.
  • Transformer (2017): Introduction of self-attention mechanisms, eliminating recurrent bottlenecks.
  • GPT Era (2018+): Massive autoregressive generative pre-trained transformers enabling rich zero-shot and few-shot reasoning.

Anatomy of an Operational Prompt

An effective prompt acts like a miniature software specification. It explicitly defines the target audience, establishes clear scope and sequence, specifies the exact presentation format (e.g., Markdown table or JSON), and sets strict constraints on length and terminology.

Module 02 Tokens, Probabilities & Sampling

Understanding How Language Models Work

#

Tokenization Engine

Models never see raw strings directly. Subword tokenizers slice words into integer token IDs. Formatting choices, code blocks, and punctuation heavily impact context window efficiency.

🌡️

Temperature & Softmax

Raw logit scores are scaled via softmax to form probability distributions. Temperature controls entropy: low values select peak probabilities deterministically; high values flatten the curve.

⚠️

Hallucination Risks

Fluency is orthogonal to truth. Because models optimize for plausible statistical continuations rather than factual verification, they readily fabricate authoritative-sounding falsehoods.

Practical Temperature Guidelines

Range Optimal Use Case Behavioral Profile
0.0 – 0.3 Code generation, math extraction, data parsing High precision, deterministic, highly repeatable outputs.
0.5 – 0.8 General QA, summarization, conversational assistance Balanced fluency and contextual variation.
0.9 – 1.2+ Brainstorming, creative writing, poetry generation Maximum novelty, higher risk of logical drift or instability.
Module 03 Alignment, SFT & RLHF

Chat Models, Human Feedback & Tools

The HHH Alignment Framework

A raw base model trained solely on web text will often complete a prompt by turning it into a quiz or spam forum post rather than answering it. Through alignment training, assistant models are optimized to be Helpful (fulfilling valid user goals), Honest (avoiding fabricated claims), and Harmless (refusing toxic or dangerous instructions).

1. Pre-training

Raw transformer pretraining on hundreds of billions of text tokens.

2. SFT

Supervised fine-tuning using curated instruction-response dialogue datasets.

3. Reward Model

Training a scoring model on human comparative preferences.

4. RLHF / PPO

Optimizing policy weights via reinforcement learning against the reward model.

Structured Chat Roles (ChatML Pattern)

SYSTEM ROLE Sets high-level instructions, behavioral constraints, and role personality.
USER ROLE Contains the human's immediate question, task, or uploaded context file.
ASSISTANT / TOOL Holds model replies and structured external API/tool execution feedback.
Module 04 Application Loops, Feedforward & Tools

Designing Applications with Language Models

Think in Loops, Not Isolated Prompts

As discussed in course module 04, an LLM application is an iterative transformation process rather than a single static prompt interaction. The application acts as a bridge between the User Domain (documents, appointments, real-world decisions) and the Model Domain (tokenized input, prompt context, and generated outputs).

1. User Goal 2. Context Retrieval 3. Prompt Assembly 4. Model Inference 5. Validate / Act

Feedforward Pipeline

The application prepares model input through four distinct stages: Context retrieval (gathering raw material), Snippetization (splitting into readable excerpts), Prioritization (ranking by relevance within token budget), and Prompt assembly.

Read-Only vs. Write-Capable Tools

Models cannot inspect live calendars or modify files independently. Applications supply tools with strict schemas. While read-only lookups are safe, write-capable tools (like modifying records or executing transactions) require strict validation and user confirmation checks.

Module 05 Static/Dynamic Context & Vector RAG

Prompt Content & Retrieval-Augmented Generation

Static vs. Dynamic Content

As explored in module 05, response quality depends heavily on which information enters the prompt. Static content defines fixed rules and task instructions, whereas dynamic content injects runtime-specific data (such as user history, preferences, or retrieved database records).

Lexical vs Neural Retrieval

Lexical search (Jaccard, BM25) matches exact query terms and error codes. Neural retrieval encodes text into high-dimensional vector embeddings, measuring semantic proximity via Cosine Similarity to find relevant paraphrases even when vocabulary differs.

Two RAG Pipelines

Pipeline A (Indexing): Offline document collection, chunking into snippets, embedding generation, and vector index storage.
Pipeline B (Request-time): Query embedding, top-$k$ nearest-neighbor retrieval, prompt assembly, and grounded generation.
